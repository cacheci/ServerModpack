# AutoModpack Quick Start Guide

So you want to start using AutoModpack? Great! Let's get you started.

> ### For more detailed information:
> - Read the [Modpack Creation page](technicals/modpack-creation) to learn how to manage your modpack
> - Read the [Configuration page](configuration/server-config) to learn how to customize AutoModpack for your needs

## Installation

1. **Download AutoModpack**: Get the latest version of AutoModpack for your Minecraft version from [Modrinth](https://modrinth.com/mod/automodpack) or [CurseForge](https://www.curseforge.com/minecraft/mc-mods/automodpack)
2. **Install AutoModpack**: Place the downloaded mod into your `mods` folder of your Minecraft instance
3. **Start your server**: Launch your Minecraft server with AutoModpack installed. This will generate the initial modpack metadata

> #### It is recommended to connect to your server with just AutoModpack installed on the client first to ensure everything works.

---

## First Connection

On first connection, AutoModpack authenticates the modpack host using a CA-signed certificate, DNSSEC AMP1, a pinned server address, or manual fingerprint verification. See the [certificate verification decision guide](technicals/certificate) to choose the right method for your server.

After verification, AutoModpack will ask you to confirm the modpack installation. Confirm it, and the modpack will download and install automatically.

Restart your game. Your server's modpack should now be loaded, and you should be able to connect, spawning in the overworld.

Downloaded mod JARs are installed in the client's `mods/` folder.

## Server Setup & Configuration

### Server Config File

**Location:** `config/servermodpack/server.json`

**Example Configuration:**
```json
{
  "modpackHost": true,
  "generateModpackOnStart": true,
  "syncedModFolders": ["mods", "mods/client_recommended"],
  "server-only-mods": ["example_server_mod"],
  "syncedConfigs": ["config/**", "!config/fancymenu/user_variables.db"]
}
```

**Key Configuration Options:**

- **`syncedModFolders`**: Directories scanned recursively for mod JARs
- **`server-only-mods`**: Mod IDs omitted from the client manifest
- **`syncedConfigs`**: Configuration files, directories, or glob patterns to send; prefix a pattern with `!` to exclude it
- **Other options**: See the [full configuration page](configuration/server-config) for detailed explanations of all settings

### Splitting Mods for Server and Client

- **Client-side mods**: Place in `mods/client_recommended` or another configured mod directory
- **Server mods**: The standard `mods` directory is scanned by default
- **Server-only mods**: Mods marked server-only in metadata and IDs in `server-only-mods` are omitted

## Client Setup & Configuration

AutoModpack automatically manages client configuration. When you connect to a server, AutoModpack will:

- Install selected mod JARs in `mods/` and sync configured files to the game directory
- Authenticate the modpack host using CA trust, DNSSEC AMP1, an explicit address pin, or the saved/manual fingerprint fallback
- Ask for confirmation to install the modpack

After installation, restart Minecraft to load the modpack.

> #### **Note:** For advanced configuration, see the [client config page](configuration/client-config).

---

## Maintaining Updates

Changes in the generated mod manifest are presented through the mod selection screen. Mods already present with the same ID, version, and SHA-1 in the client's own `mods/` directory are hidden. A mod is selected by default only when a local mod has the same ID and the server version is greater by Java string comparison. Choices apply to the current game session. Run `/automodpack generate` after changing files when `generateModpackOnStart` is disabled.

## Troubleshooting

> #### **Important:**

> - Make sure your server runs and is accessible without AutoModpack
